4468-PDF-Translator —— 使用说明（快速上手）
================================================

一个把 PDF 文档用 AI 大模型翻译成中文（或其它语言）的本地小工具，
译文会写回原来位置，图片和表格线都保留。


【一、怎么启动】
------------------------------------------------
方式一（推荐）：双击   启动.bat
    · 会自动检查并安装缺失的依赖
    · 会自动打开浏览器
    · 关闭那个黑窗口就是停止服务

方式二：在命令行里执行
    pip install -r requirements.txt
    python -m src.main

启动后浏览器访问：  http://127.0.0.1:8765/
（端口被占用会自动换成 8766、8767…… 控制台会提示实际地址）


【二、怎么用】（界面上三步）
------------------------------------------------
1. 把 PDF 拖到左上角的上传区，等它解析完
   —— 会显示页数、大小、识别出多少个可翻译段落

2. 在「翻译设置」里：
   · 服务商：默认 DeepSeek
   · API Key：填你自己的密钥（sk- 开头）
   · 点【测试连接】确认能通（不通会提示中文原因）

3. 选好目标语言和翻译模式，点【开始翻译】
   —— 进度条、阶段、日志会实时刷新
   —— 完成后在右侧预览译文页面，在下面下载文件


【三、先不花钱试一下】
------------------------------------------------
把服务商切到「模拟翻译（仅调试）」。
它不联网、不调用大模型、几秒出结果，
用来确认 PDF 的解析和排版效果是否让你满意。
满意了再换回真实模型。


【四、两种模式怎么选】
------------------------------------------------
嵌字版 / 仅译文（mono）—— 默认，推荐
    擦掉原文，在原来的位置、原来的基线上写入译文。
    版式、图片、插图、表格线（矢量图形）全部原样保留，
    只有文字被换成中文 —— 看起来就是"原来那份文档变成了中文"。

    具体做了这些事：
      · 字体风格跟着原文走：衬线配衬线（宋体一类）、
        无衬线配无衬线（黑体一类）、加粗配真实粗体字重；
      · 首行落在原文首行的基线上，多行段落沿用原文的行距；
      · 字号能不改就不改（放不下才缩），译文偏短时把字距
        拉开填满原来的行宽；
      · 汉字与英文/数字交界处加一点间隙，中文标点不会跑到行首；
      · 译文里的英文单词、学名（Vipera berus）用内置拉丁字体，
        保证在 PDF 里能正常搜索、复制（不会被换成怪字符）。

双语对照（dual）—— 用于校对、学习
    保留原文，译文紧跟每段下方，中间有一条浅色分隔线。
    如果版面太紧凑，程序会自动把字号缩小到两边都放得下
    （不会让文字互相盖住）。这种文档建议改用「嵌字版」。

关于字体：程序会自动从本机已装的中文字体里挑（不用下载任何东西）。
想指定自己的字体，展开「嵌字字体」填字体文件路径即可；
建议用 TrueType（.ttf / .ttc），CFF/OTF 字库会让产物体积膨胀到好几 MB。


【五、会产出哪些文件】
------------------------------------------------
· xxx_mono.pdf          嵌字版 PDF（保留原版式，主交付物）
· xxx_dual.pdf          双语对照 PDF
· xxx_bilingual.md      逐段对照的 Markdown（方便复制、检索）
· xxx_translation.txt   纯译文文本
· xxx_segments.json     分段对照数据（含坐标，便于二次加工）

文件位置：work\outputs\<任务ID>\


【六、扫描版 PDF（图片型）怎么翻译】
------------------------------------------------
扫描件、影印件没有文字层，直接翻译会是空的。本工具内置了 OCR，
几步就能用起来：

第一步　装 OCR 依赖（只需一次）
    pip install onnxruntime numpy
    （双击 启动.bat 也会自动帮你装）

第二步　下载 OCR 模型（只需一次，约 21 MB，需要联网）
    python -m src.main --download-ocr ch
    也可以在界面里点「下载模型」按钮。

第三步　正常翻译
    上传扫描件 → 在「OCR 扫描件识别」里确认
        OCR 模式 = 自动（仅扫描页）
        识别语言 = 中英混排
    → 开始翻译

小技巧：界面里有「在这一页试识别」按钮，
选一页点一下，就能先看看识别出多少行、每行置信度多少。
觉得不准就换语言模型，或把「识别精度(DPI)」从 300 提到 400。

语言怎么选：
    中英混排(ch)  中文文档、中英夹杂的文档 —— 默认，最常用
    英文(en)      纯英文扫描件
    日文(japan)   日文
    拉丁语系(latin)  法/德/西/葡 等
    其它还有 韩文/西里尔(俄)/阿拉伯/泰/希腊/天城文

注意：
  · OCR 是可选功能，不装不影响普通 PDF 翻译，也不会拖慢它
    （默认只在页面"没有文字层"时才走 OCR）。
  · 识别精度受扫描质量影响很大：模糊、倾斜、手写的效果会明显下降。
  · 扫描件里的公式、图表文字 OCR 基本不可用，建议保留为图片。


【七、常用设置】（改完记得点「保存为默认设置」）
------------------------------------------------
· 术语表       每行一条，写成   原文=译文
               例如：Transformer=变换器
               术语表优先级最高，强制统一译名
· 页面范围     all 表示全部；也可以写  1-5,8,11-13
· 并发数       默认 4，网络好可以调到 6~8，明显提速
· 每批段落数   默认 12，调大能减少请求次数、更省钱
· 字号缩放     译文比原文显得太大/太小时调这个
· 自定义提示词 想改翻译风格（比如更口语化）就改这里

配置文件（config\config.json）里另有三个"保真"开关，默认全开，
在界面上不显示，出问题可以单独关掉：

  numeric_guard      数值保护
      译文里的数字与原文不一致时，程序会带着"这些数字必须原样保留"
      再问一次模型；还不对就保留该段原文（不猜、不糊）。
      日志会写"数值校验：初检 N 段…"，明细最多 5 条。
      实测 2697 段里初检失配 8 段（0.30%），一次重试修好 7 段。

  symbol_fallback    数学符号字形降级
      译文里的 ≤ ≥ × ° √ ∑ ∛ ₁₀ ↗ 这类符号，如果当前字体没有字形，
      先去本机字体里找一个有的（保留原符号）；真找不到才换成
      ASCII 写法（≤ → <=）。关掉它就回到旧行为：缺字形的符号
      会画成空白方块，从 PDF 里复制出来是空的。

  table_cell_clamp   表格单元格内约束
      识别出表格单元格后，译文不越过格子边界，避免压到旁边的格子。

  table_row_clamp    表格行内约束（三线表靠它）
      只有横线的表格（三线表）识别不出单元格，改用页面上的**横线**
      切出"行"，把译文约束在行内。实测全库 46 份：能切行 160 页，
      落在行里的可翻译段落 2679 段，其中 801 段（29.9%）原来会
      往下借走最多半页的空白 —— 现在被拦在行内。


【八、常见问题】
------------------------------------------------
问：译文里的公式符号变成了空白方块？
答：正常情况不会 —— 程序会去本机字体里找有该字形的字体来画。
    如果确实出现了方块，检查 config\config.json 里的
    symbol_fallback 是不是被改成了 false；另外确认本机装了
    MS Gothic 或微软雅黑这类带数学符号的字体。

问：译文压到了表格的下一行？
答：请确认 config\config.json 里 table_cell_clamp 与 table_row_clamp
    都是 true。若是"文字明显变小"而不是压行，那是程序在保证不越格 ——
    表格行的高度就那么大，译文长了只能缩字号。把字号缩放调小一点
    或改用双语模式可以缓解。

问：提示「未发现可提取的文本」？
答：这是扫描版 PDF（整页都是图片），没有文本层。
    请按上面【六】开启 OCR，或先用 OCRmyPDF 之类工具处理成可搜索 PDF。

问：怎么完全离线用？
答：可以。大模型选「本地 Ollama」；OCR 模型下载一次之后也是离线的。

问：翻译到一半把网页关了，会中断吗？
答：不会。任务在后台跑，重新打开页面会接着显示进度。
    但把命令行窗口关掉会中断任务。

问：为什么双语模式下有的字变小了？
答：那段文字下方空间不够，放不下"原文+译文"，
    程序自动缩小字号以保证不互相覆盖。日志里会提示有多少段这样处理了。
    这种文档用「嵌字版」效果更好。

问：嵌字版里标题没有加粗，怎么办？
答：先看「嵌字字体」里的"当前匹配结果"：
    · 如果显示"伪粗体"，说明本机没有匹配的粗体中文字体，
      程序改用描边模拟加粗；
    · 如果匹配到的是常规字重，可以在「指定粗体字体文件」里
      填一个粗体字体路径（例如 C:\Windows\Fonts\msyhbd.ttc）。
    另外，"加粗小标题和正文被排进同一个文本框"的情况，
    程序会自动按行级风格把它们拆开，让标题拿回粗体。

问：译文里的英文能搜到吗？
答：能。英文/数字一律用内置拉丁字体渲染（不占体积），
    保证 PDF 里搜索、复制都正常。这一点很关键 —— 用中文字体
    渲染英文时，有些字库会把空格、连字符映射错（搜不到多词短语）。

问：产出 PDF 突然变得很大（好几 MB）？
答：说明字体没能子集化。常见原因是选到了 CFF/OTF 字库
    （例如 Noto Sans SC 的 .otf 版本），这类字库 MuPDF 无法正确
    子集化。在「嵌字字体」里改用一个 TrueType 字体（.ttf / .ttc）即可。
    程序会在日志里提示这种情况。

问：重跑同一份 PDF 会重复扣费吗？
答：不会。译文有本地缓存，相同内容不再请求大模型。

问：怎么换成别的模型？
答：在服务商下拉里选（硅基流动 / OpenAI / Kimi / 智谱 / 通义 / 本地 Ollama），
    或者选「自定义」自己填 Base URL 和模型名（任何 OpenAI 兼容接口都行）。

问：能完全离线用吗？
答：可以。装好 Ollama 并 pull 一个模型（例如 qwen2.5:7b），
    服务商选「本地 Ollama」，全程不联网。
