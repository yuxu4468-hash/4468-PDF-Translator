## Goal

译文**不越出所属表格单元格**、不压到相邻单元格：识别出单元格后，把段落的
可用高度收紧到格子边界内。

不做的事（设计 §2 明确）：不重绘表格线、不做列宽自适应、不改擦除矩形、
不改绘制方式、不改字体选择 —— 本阶段只收紧一个上界。

## Architecture

**分层归因**：单元格约束是**排版量度的边界条件**，不是绘制问题，也不是解析问题。
所以改动落在两处：

1. **解析层**（`pdf_parser` + `layout`）：把"这一格到哪儿为止"这个事实**识别出来并
   存到段落上**。解析层不参与排版决策，只提供事实。
2. **排版层**（`typesetter._build_page_plan`）：在算 `max_height` 的地方收紧它。
   这是唯一一个"能排多大空间"的 owner，改这里不会产生平行实现。

```
parse_page()
  ├ layout.table_regions(page)  → 表格**区域**（已有，用于区分表头/页眉）
  └ layout.table_cells(page)    → 单元格矩形列表（新增）
       ↓ 段落中心落入某格
     paragraph.cell_bbox / PageInfo.cells（新增字段）
       ↓
_build_page_plan()
  max_height = 原框高 + 邻居让出的空白        （既有逻辑）
  max_height = min(max_height, 到格边的距离)  （新增，只收紧）
       ↓
  fit_text() 用这个上界二分字号 —— 挤不下就缩号，缩到底还能挤出去则由
  既有的 overflow 统计报出来
```

**一句话概括取舍**：宁可字号小一点，也不要压到隔壁单元格。

## Tasks

### Task 3.1 — layout：单元格识别与绑定

要点（实施时的取舍）：

- `table_cells()` **不抛异常**，识别失败返回空列表 —— 排版不能因为表格识别失败而
  整体失败。
- 单元格去重：合并单元格会在多行里重复出现，按取整后的矩形去重，避免白算。
- 过滤过小的矩形（`min_side=2.0`）：`find_tables()` 偶尔会给出退化成一两点的格。
- 绑定用**中心点**而不是面积重叠：单元格是硬边界，一段文字必然属于唯一一格；
  面积重叠会让识别歪了的段落同时"属于"两格，取哪个都说不清。

### Task 3.2 — models / pdf_parser：把事实存下来

新增字段一律带默认值，且**不改 `to_dict()`**：这是内部契约，不进接口。

### Task 3.3 — typesetter：只收紧、不放大

```python
def _cell_room(cell_bbox, original, is_vertical, flipped) -> float | None:
    if not cell_bbox:
        return None
    if is_vertical:
        return float(cell_bbox[2]) - original.x0      # 竖排沿"宽"叠放
    if flipped:
        return original.y1 - float(cell_bbox[1])      # 180° 倒排向上
    return float(cell_bbox[3]) - original.y0          # 常规向下


def _clamp_to_cell(paragraph, original, is_vertical, flipped, max_height) -> float:
    room = _cell_room(paragraph.cell_bbox, original, is_vertical, flipped)
    if room is None or room <= 0:
        return max_height
    floor = max(4.0, original.width if is_vertical else original.height)
    if room <= floor:
        return max_height
    return min(max_height, room)
```

**下限为什么卡在"段落自己原来的框"**：原文本身就占着这么大，压到它以下既解决不了
问题、又会把一段本来正常的段落改小；万一某段被错误地绑到一个偏小的格子上，压下去
就是**误改**。宁可漏检不可误改 —— 所以约束只能**收回借来的空间**，不能侵占原文的框。

**一处对设计原文的修正（已在本文件与设计文档中如实记录）**：设计写的是
"约束（仅 mono 嵌字模式）"，但实施时发现 `max_height` 在**进入模式分支之前**就已算好、
两种模式共用，所以收紧对 mono 与 dual 一并生效。dual 的向下扩展同样会压到下一行，
一并收紧是要的效果；若只想对 mono 生效，需要在分支内各算一次，得不偿失。

## 已知限制（如实记录，未做）

- **三线表的横线挡不住译文**：`find_tables()` 识别不出单元格，退化路径只避让
  相邻段落的**文字**，所以译文可以越过横线（实测一份合成三线表下沿越过横线
  3.5pt，但停在下一段文字之上）。要彻底解决需要"按横线切行"的新机制 ——
  属于设计 §2 的非目标（不重绘表格线、不做列宽自适应）之外的**新机制**，
  本阶段明确不做，留给后续按需评估。
- **OCR 段落没有单元格信息**：OCR 段落是在解析之后追加的，`cell_bbox` 为 None，
  走退化路径。
- **误绑定的兜底**：`find_tables()` 偶尔会给出与段落并不匹配的格子。靠
  `_clamp_to_cell` 的"下限卡在原框"把损害限制在"不能借用邻居空间"，
  不会把段落压得比原文还小。
