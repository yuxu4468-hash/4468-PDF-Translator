## Goal

译文里出现**当前渲染字体没有字形**的数学符号时，不再画成空白方块（notdef）：

1. 先在本机字体里找**真有这个字形**的字体，用它画（保住原符号）；
2. 本机也找不到时，退到 **ASCII 等价写法**（`≤` → `<=`）；
3. 仍无法渲染的，保持现有 `sanitize_for_font` 语义（丢弃 + 告警）。

## Architecture

**分层依据（先归因再改层）**：符号被画成方块，根因在**绘制层选字体**，不在解析层也不在
翻译层。解析层已经把字符原样带出来了（回读校验能证明：字符在，只是提取为空 —— 说明
字形缺失发生在写 PDF 时）。

本项目有**两条互不相同的绘制路径**，降级链必须分别对待：

```
排版计划 build_plan()
  ├ 横排（rotation 0/180）→ TextWriter + FontPair.runs()
  │    每个字符按 resolve() 路由到 cjk / latin 两个字体
  │    ⇒ 可以**按字符换字体**：这里能真正保住原符号
  │    ⇒ 降级链 1) 路由字体 2) 本机符号字体 3) ASCII 等价
  │
  └ 竖排（rotation 90/270）→ page.insert_textbox(fontname=单个字体)
       insert_textbox 只接受**一个**字体名，没法按字符切换
      ⇒ 降级链 1) 该字体 2) 本机符号字体**不可用** 3) ASCII 等价
```

**所以竖排的符号保护只能靠 ASCII 等价**，这是 `insert_textbox` 的硬约束，
不是设计选择（历史上已经为它做过一次妥协：竖排的 `ascii_safe` 字体筛选）。
本阶段顺带修一个**既有缺陷**：竖排的 `sanitize_for_font` 一直传的是
"cjk + latin 字体对"，但实际绘制只用 cjk 那一个字体，于是"判定说有字形、
实际画成方块"（例如 `U+2010` 那一类问题）。改为按**实际绘制字体**判定。

## 实测依据（写代码前已经拿到，不靠猜）

**23 个缺失符号全部有落点，且落点能收敛到 1 个字体。**

| 候选排序依据 | 结果 |
| --- | --- |
| 逐个 first-match（subset_safe → 非常量 → cjk_ok → 偏好 → 名字） | 落到 **4 个**字体，其中一个是 JhengHei **Light**（细体，观感不对） |

**8/8 组全部原样提取**。即"换字体渲染"这条路真的能修好，不是把方块从一处搬到另一处。

## Tasks

### Task 2.1 — fonts：按码位找符号落点

```python
#: 符号字体偏好（越靠前越优先）
_SYMBOL_PREFERENCE = (
    "ms gothic", "yu gothic", "malgun gothic",
    "microsoft jhenghei", "microsoft yahei", "dengxian",
    "simsun", "simhei", "heiti", "songti", "kaiti",
    "source han", "noto sans", "思源", "黑体", "宋体",
)


def _symbol_candidates() -> list[FontFace]:
    faces = list(_pack_faces()) + list(system_faces())
    faces.sort(key=lambda face: (
        0 if face.subset_safe else 1,     # 能正确子集化（CFF 会让产出膨胀）
        0 if not face.variable else 1,    # 可变字体 MuPDF 只取第一个实例
        0 if not face.light else 1,       # 细体画符号明显偏轻
        0 if face.cjk_ok else 1,          # 反查表可信
        0 if face.ascii_ok else 1,
        _symbol_preference_rank(face.name),
        face.name,
    ))
    return faces


def resolve_symbol_face(code: int) -> "FontFace | None":
    """为"当前字体没有字形"的码位找第一个本机有该字形的字体。按码位缓存。"""
    with _SYMBOL_LOCK:
        if code in _SYMBOL_FACE:
            return _SYMBOL_FACE[code]
    found = None
    for face in _symbol_candidates():
        try:
            if load_font(face).has_glyph(code):
                found = face
                break
        except Exception:
            continue
    with _SYMBOL_LOCK:
        _SYMBOL_FACE[code] = found
    return found
```

`invalidate()` 里一并 `_SYMBOL_FACE.clear()`（装了新字体后不能沿用旧结论）。

**为什么排序里 `light` 在 `cjk_ok` 之前**：细体是**观感缺陷**（数学符号用细体画会
比周围正文明显轻），而 `cjk_ok` 是针对汉字兼容区的探测，与拉丁/数学码位的反查正确性
只是弱相关。实测里唯一被"细体优先"害到的就是 JhengHei Light。

### Task 2.2 — typesetter：FontPair 支持符号落点

`FontPair` 新增两个字段：`symbol_fallback: bool = True` 与
`_char_font: dict`（码位 → 实际字体，热路径上只是一次查表）。

```python
def font_for_code(self, code: int) -> fitz.Font:
    cached = self._char_font.get(code)
    if cached is not None:
        return cached
    font = self.cjk if is_cjk_code(code) else self.latin
    if self.symbol_fallback and not font.has_glyph(code):
        face = font_lib.resolve_symbol_face(code)
        if face is not None:
            font = font_lib.load_font(face)
    self._char_font[code] = font
    return font
```

**必须在度量层而不是绘制层换字体**：`text_length` / `line_width`（折行、居中、
字距拉伸都依赖它）与 `runs()`（实际绘制）都从这一处取字体。只在绘制处换，
"量出来"和"画出来"就会不一致，行会排歪。

`runs()` 相应改成按**字体对象**分组（原来按"是不是 CJK"分组，符号落点字体既不是
中文字体也不是拉丁字体，必须自己成一段），第三个返回值退化为"只用于日志的标签"。

`has_glyph()` 也走这条链 —— 于是 `sanitize_for_font` 对 `FontPair` 判定时，
有落点的符号不会被降成 ASCII（保真度优先）。

### Task 2.3 — typesetter：等价写法兜底表

表值可以是字符串，也可以是**候选序列**（按优先级）。这不是为了好看 ——
是实测逼出来的：`∅` 在德语技术文档里是**直径**符号（`∅ 1,6 m`），
朴素地按"空集"写成 `empty` 会把"直径 1.6 米"变成"空的 1.6 米"。
`Ø` 形近且常见（实测微软雅黑/等线都有），于是 `("Ø", "dia", "empty")`：
形近优先，真没有才退到 ASCII 拼写。

```python
SYMBOL_ASCII_FALLBACK = {
    "≤": "<=", "≥": ">=", "≠": "!=", "≈": "~=", "×": "x", "÷": "/",
    "²": "^2", "³": "^3", "¹": "^1", "⁰": "^0", "⁻": "^-", "⁺": "^+",
    "₀": "_0", "₁": "_1", "₂": "_2", "₃": "_3", "₄": "_4",
    "∑": ("Σ", "sum"), "∏": ("Π", "prod"), "∫": "int", "√": "sqrt", "∞": "inf",
    "±": "+/-", "∓": "-/+", "⋅": "·", "·": "⋅", "∘": "o", "∂": "d",
    "∇": "grad", "Δ": "Delta", "δ": "delta", "π": "pi", "μ": "u",
    "Ω": "Ohm", "°": "deg", "′": "'", "″": '"', "‰": "0/00", "‱": "0/000",
    "←": "<-", "→": "->", "↔": "<->", "⇒": "=>", "⇔": "<=>",
    "∈": "in", "∉": "not in", "⊂": "subset", "⊆": "subseteq",
    "∪": "union", "∩": "intersect", "∀": "forall", "∃": "exists",
    "∠": "angle", "⊥": "perp", "∥": "parallel",
    "∅": ("Ø", "dia", "empty"),      # 直径符号，不是空集
    "ⁿ": "^n", "∛": "cbrt", "½": "1/2", "¼": "1/4", "¾": "3/4",
    "↗": "up-right", "↘": "down-right",
}


def _renders(font, text: str) -> bool:
    return bool(text) and all(font.has_glyph(ord(char)) for char in text)


def _equivalent_forms(char: str) -> tuple[str, ...]:
    value = SYMBOL_ASCII_FALLBACK.get(char)
    if value is None:
        return ()
    return (value,) if isinstance(value, str) else tuple(value)
```

`sanitize_for_font(text, font, allow_ascii=False)`：`allow_ascii` 默认 **False**，
由调用方按配置传入 —— 这样关掉开关时行为与改造前**逐字节一致**
（缺字形的字符原样保留、画成 notdef），不做静默改变。
每个候选的每个字符都必须在该字体里有字形，否则等于把方块从一个码位搬到另一个码位。

顺带修掉一个与 M1 无关但同处的缺陷：`FontPair.text_length` 原本自己写了一套
"中英间隙"判断，与 `needs_inter_space` 在"数字后接中文标点"（`6，体积`）和
"汉字后接空格"（`长 5`）上结论相反，导致同一段文字 `text_length` 与 `line_width`
算出两个宽度（实测差 6.5pt）。现在统一走 `needs_inter_space`。

**实测补充（这一节是事后回填的）**：A/B 出片复核发现，这份语料里真正会丢符号的
**只有竖排** —— 鳄类准则里 22 处 `∅ 1,6 m` 全部是旋转 -90° 的表格单元格，
而 `∅` 在内置字体与中文字体里都没有字形，竖排又只能用一个字体，
所以这张等价写法表在竖排里是**唯一**手段（不是"最后兜底"）。
